# 兼容性矩阵

> 最后更新：2026-11-20
> 目标区间：**Android 11 (API 30) ~ Android 15 (API 35)**
> 新增能力时必须在下表补一行，并写明降级路径。

---

## 一、能力 × 系统版本

| 能力 | 依赖 | 最低 API | 低版本降级 |
|---|---|---|---|
| 节点树读取 | `AccessibilityNodeInfo` | 21 | — |
| 语义点击 | `performAction(ACTION_CLICK)` | 21 | 失败则坐标手势 |
| 手势 | `dispatchGesture` | 24 | 无降级（24 以下不支持） |
| 全局动作 | `performGlobalAction` | 21 | `lock` 需 API 28+ |
| 截图 | `takeScreenshot` | **30** | `MediaProjection`（需授权+常驻通知） |
| 窗口枚举 | `getWindows()` | 21（需 flag） | 回退 `rootInActiveWindow` |
| hint 字段 | `getHintText` | 26 | 返回空串 |
| Shizuku | `dev.rikka.shizuku` | 23 | 回退 root，再回退"不可用" |

> 当前 `minSdk=30`，因此截图不需要 MediaProjection 降级；**若将来下调 minSdk，必须补上该分支**。

## 二、ROM 差异（实测）

| ROM | 现象 | 影响 | 应对 |
|---|---|---|---|
| MIUI / HyperOS（Xiaomi houji，模拟器） | 开机把 `accessibility_enabled` 置 0，但保留组件列表 → 设置页显示"已开启" | 引擎启动后无法操作 | UI 显示"总开关被系统关闭"，引导去点弹窗；详见踩坑记录 |
| MIUI / HyperOS | 首次授予需要过系统弹窗"要允许…完全控制您的设备吗" | 写 settings 无效 | 只能走系统 UI |
| 通用 AOSP | 重启后无障碍保持 | 正常 | — |

> 厂商层行为无法用应用代码绕过；`A11yState` 已做三态区分，报告里会如实标注。

---

## 三、权限与用户操作成本

| 项 | 是否需要用户操作 | 备注 |
|---|---|---|
| 无障碍服务 | 是（一次性 + 部分 ROM 每次重启） | 核心权限 |
| 电池优化白名单 | 建议 | 否则息屏断连 |
| 通知权限（Android 13+） | 是 | 前台服务通知 |
| Shizuku | 可选 | 仅"脱离 PC 执行 shell"时需要 |

---

## 四、屏幕与坐标

| 项 | 处理 |
|---|---|
| 分辨率差异 | 所有坐标均为设备像素；手势按实际屏幕尺寸计算（`resources.displayMetrics`） |
| 横竖屏 | 未做专门处理；坐标由节点 bounds 推导，理论上自适应 |
| 密度差异 | 不影响（不用 dp 参与定位） |
| 折叠屏/多窗口 | 未验证 |
