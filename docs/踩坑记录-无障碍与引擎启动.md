# 踩坑记录：无障碍授权与引擎启动

> 环境：MuMu 模拟器（Xiaomi houji 镜像，Android 15）
> 记录时间：2026-11-19　|　起因：在此问题上反复来回，浪费约 40 分钟

---

## 0. 一句话结论

这台 ROM 有**三个彼此独立的状态**，只看其中一个必然误判。设置页只反映第 2 个，所以它会"骗人"。

---

## 1. 必须同时看三个值

| # | 事实 | 怎么读 | 含义 |
|---|---|---|---|
| 1 | **总开关** | `settings get secure accessibility_enabled` | 系统是否允许无障碍工作（1/0） |
| 2 | **组件列表** | `settings get secure enabled_accessibility_services` | 设置页据此显示"已开启" |
| 3 | **真实绑定** | `dumpsys accessibility \| grep 'Bound services'` | **唯一能干活的状态** |

```
✅ 1=1  2=含本应用  3=Bound 里有本应用   → 正常
🟡 1=1  2=含本应用  3=空                 → 假授权，必须重新 toggle
🟠 1=0  2=含本应用  3=空                 → ROM 开机把总开关关了
❌ 1=0  2=null      3=空                 → 从未授权 / 被清空
```

---

## 2. 五个坑

### 坑 1：重启后"已授权"，其实没生效

**症状**：重启 → App 显示未连接 → 进设置看是"已开启" → 关掉再打开一次就好了。

**根因**：这个 ROM 开机把 `accessibility_enabled` 置 0，但**保留组件列表**。设置页读的是列表，于是显示"已开启"。

**处理**：设置 → 无障碍 → 点进本服务 → 关掉再打开 → 系统弹窗「允许」。

**不要做**：`settings put secure accessibility_enabled 1`。实测值会变，但**系统不会绑定**，还会让状态更乱。

---

### 坑 2：force-stop 本应用 = 自杀

**症状**：执行 `adb shell am force-stop com.mobileappauto.engine` 之后，无障碍彻底消失：

```
master   = 0
services = null
Bound services:{}
```

**根因**：force-stop 让包进入 stopped 状态，系统移除其无障碍注册。

**处理**：只能重新走设置授权。

**规则（重要）**：测试隔离只 force-stop **被测应用**，永远不要碰引擎自己。

```bash
# ✅ 正确
adb shell am force-stop com.android.settings
# ❌ 自杀
adb shell am force-stop com.mobileappauto.engine
```

---

### 坑 3：覆盖安装后"列表里有，但不绑定"

**症状**：`install -r` 之后 `dumpsys` 显示 Enabled 有、Bound 空；点按钮没反应。

**根因**：安装过程打断了无障碍绑定，系统没重新拉起。

**处理**：进详情页关→开。实在不行才卸载重装（**会丢 token 和配置**）。

**注意**：`install -r` 有时也能保留正常绑定（这次 21:41 那次就保留了）。**装完必须读一次三态**，别假设。

---

### 坑 4：令牌不一致 → 看着像死循环

**症状**：手机一直"正在连接 10.0.2.2:7913"，hub 日志疯狂刷：

```
[!] ('127.0.0.1', 62752) 令牌不匹配，已拒绝
[!] ('127.0.0.1', 62754) 令牌不匹配，已拒绝
...
```

**根因**：手机端令牌变了（重装/手动改），而 hub 还是旧令牌启动的。每 2 秒重连一次，看起来就是卡死。

**处理**：比对两边令牌，用正确令牌重启 hub。

**教训**：我改过令牌后忘了重启 hub，把"令牌不匹配"误判成"引擎卡死"，白折腾了一轮。

---

### 坑 5：`adb reboot` 在 MuMu 上会挂死

**症状**：`adb devices` 一直 `offline`，20 分钟不恢复，进程还在但 guest 不响应。

**处理**：在 MuMu 里手动重启实例。

**替代**：用软重启 `adb shell "stop; sleep 2; start"`（需要 `adb root`，模拟器一般可以）。

## 3. 一条命令定位

```powershell
powershell -ExecutionPolicy Bypass -File scripts\check-state.ps1 -Token <令牌>
```

输出示例（全绿时）：

```
=== 设备 ===
✅ adb 设备                             emulator-5554  device
=== 无障碍（三个独立事实，别混为一谈）===
✅ 总开关 accessibility_enabled          1
🟡 组件在启用列表里                        是（设置页会显示"已开启"）
✅ 系统真的绑定了服务                       是
=== 引擎 ===
✅ 应用进程                               pid=10063
✅ EngineService                       运行中
   设备内令牌                              <token>
✅ 与传入令牌一致                          是
=== 反连通道 ===
✅ hub /v1/ping                        200 正常
=== 结论 ===
无障碍 + 引擎都正常。
```

出问题时最后一行会直接告诉你该做什么，不用再猜。

## 4. 标准恢复流程

1. 跑 `check-state.ps1`，看「结论」
2. 按结论操作，通常是这一步：
   **设置 → 无障碍 → 点「A11y Driver 执行引擎」→ 系统弹窗「允许」**
3. 回到 App 点「② 启动执行引擎」，或直接：
   ```bash
   adb shell am start-foreground-service -n com.mobileappauto.engine/.EngineService
   ```
4. 再跑一次 `check-state.ps1` 确认全绿

**唯一可靠的授权方式只有系统 UI 的那个弹窗**。写 settings、删列表、重建列表，全部实测无效。

## 5. 调试时的正确姿势

| 想做的事 | 别用 | 该用 |
|---|---|---|
| 启动引擎 | 点按钮 / force-stop 后重启 | `am start-foreground-service -n .../.EngineService` |
| 停止引擎 | `am force-stop` | `am stopservice -n .../.EngineService` |
| 刷新 App 界面 | 反复点 | `input keyevent 3`（回桌面）+ `am start -n .../.MainActivity` |
| 重置被测应用 | — | `am force-stop <被测包名>` |
| 改令牌 | 运行中直接改 | 先停引擎 → 改 → 启动 → **同步重启 hub** |

补充两条判据：

- **截图前先看焦点**：`dumpsys window | grep mCurrentFocus`，焦点不对说明前一步没生效。
- **触摸无反应先按返回键**：`input keyevent 4`。有反应说明是坐标/布局问题；没反应说明应用卡了，别继续点。

## 6. 时间线复盘：这 40 分钟是怎么绕进去的

| # | 我做了什么 | 结果 | 本该怎么做 |
|---|---|---|---|
| 1 | 为验证"重启后是否保留"执行 `adb reboot` | MuMu 挂死，adb offline 20 分钟 | 用 `stop/start` 软重启 |
| 2 | 设备回来后直接改 settings 想恢复授权 | 无效，状态更乱 | 直接走系统 UI 授权 |
| 3 | 反复 `settings put` / 删列表 / 重建 | 组件列表被清空 | 停手，先读三态 |
| 4 | `am force-stop` 引擎想重置界面 | 无障碍被系统移除 | 用 `am stopservice` |
| 5 | 改完令牌没重启 hub | 引擎无限重连，误判"卡死" | 改令牌立刻重启 hub |
| 6 | 用 `Invoke-WebRequest` 探活 | PowerShell 5.1 走代理假失败 | 用 `curl -w %{http_code}` |

**共同点**：每一次都在"没确认当前状态"的前提下动手，结果越修越乱。
