# 接口文档

> 版本：v1.0　最后更新：2026-11-20
> 机器可读版本：[`openapi.yaml`](./openapi.yaml)
> **文档与实现不一致时，以本文档为准，实现算缺陷。**

---

## 0. 通用约定

| 项 | 约定 |
|---|---|
| 协议 | HTTP/1.1，JSON 用 `application/json; charset=utf-8` |
| 鉴权 | 所有请求带 `X-Auth-Token: <令牌>` |
| 时间单位 | 一律毫秒，字段名以 `Ms` 结尾 |
| 坐标 | 屏幕绝对像素，左上角为原点 |
| 成功判定 | `ok: true`；失败为 `ok: false` + `error` |
| 中文字符 | 一律 UTF-8，不做转义 |
| 并发 | 同一条反连连接支持多请求在途，响应按 `id` 分发；长任务不会阻塞 `/v1/cancel` |
| 心跳 | hub 每 10s 向手机发 `{"type":"ping"}`，30s 无 `pong` 判定离线 |

### 部署形态

```
脚本 ──▶ 编排器 :7920 ──┬── /v1/ui/*    ──▶ 手机引擎（无障碍）
                        ├── /v1/shell   ──▶ adb（设备 shell）
                        └── /v1/logcat  ──▶ adb（设备日志）

手机 ──反连 :7913──▶ hub :7912 ──HTTP──▶ 脚本
```

三种入口的路径一致，脚本切换只改 `base URL`。

### 错误码

| `error` | HTTP | 含义 | 处理建议 |
|---|---|---|---|
| `UNAUTHORIZED` | 401 | 令牌缺失或错误 | 检查 `X-Auth-Token` |
| `ACCESSIBILITY_NOT_READY` | 200 | 无障碍未绑定 | 见 `docs/踩坑记录` |
| `NO_WINDOW` | 200 | 拿不到活动窗口 | 稍后重试 |
| `NOT_FOUND` | 200 | 选择器未命中 | 放宽条件或加等待 |
| `EMPTY_CMD` | 400 | shell 命令为空 | — |
| `SHELL_UNAVAILABLE` | 200/503 | 无 shell 通道 | 换 ADB 或装 Shizuku |
| `SHIZUKU_PERMISSION_DENIED` | 200 | Shizuku 未授权 | 应用内点「申请 Shizuku」 |
| `SHIZUKU_PROCESS_UNSUPPORTED` | 200 | SDK 版本不支持 | 降级到 ADB 通道 |
| `SCREENSHOT_FAILED` | 500 | 截图失败（可能 FLAG_SECURE） | 检查页面类型 |
| `ACTION_FAILED` | 200 | 找到节点但动作执行失败 | 换坐标或加重试 |
| `CANCELLED` | 200 | 被 `/v1/cancel` 中断 | — |
| `TIMEOUT` | 200 | 等待超时 | 加大 timeoutMs |
| `SCROLL_TIMEOUT` | 200 | 滚动总预算（12s）耗尽 | 缩小查找范围 |
| `BAD_ARGS` | 200 | 参数不合法 | 检查必填字段 |
| `UNKNOWN_COMMAND` | 200 | 未知命令 | 检查拼写 |
| `NO_ROUTE` | 404 | 路径不存在 | 检查路径 |

## 1. 设备引擎接口

### 1.1 `GET /v1/ping` — 存活检查

```json
// 200
{"ok": true, "accessibility": true, "package": "com.android.settings", "sdk": 35, "id": "1"}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `accessibility` | bool | 无障碍是否已绑定（唯一可信信号） |
| `package` | string | 事件缓存的前台包名，可能滞后 |

---

### 1.2 `GET /v1/capabilities` — 能力清单

```json
// 200
{
  "ok": true,
  "ui": {"available": true},
  "accessibility": true,
  "shell": {"available": false, "kind": "none", "via": "on-device",
            "hint": "未检测到 Shizuku 或 root；可改用 PC 侧 ADB 通道（/v1/shell）"}
}
```

---

### 1.3 `GET /v1/hierarchy` — 节点树

```json
// 200
{
  "ok": true,
  "data": {
    "ok": true,
    "package": "com.android.settings",
    "nodeCount": 54,
    "root": { "...": "见 Node 结构" }
  }
}
```

### Node 结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `class` | string | 完整类名 |
| `text` | string | 文本 |
| `desc` | string | contentDescription |
| `hint` | string | hintText（API 26+） |
| `id` | string | `com.foo:id/btn` |
| `pkg` | string | 所属包名 |
| `bounds` | int[4] | `[left, top, right, bottom]` |
| `center` | int[2] | `[x, y]` |
| `clickable/longClickable/scrollable/editable/checkable/checked` | bool | 状态位 |
| `selected/focused/enabled/visible` | bool | 状态位 |
| `depth` | int | 层级 |
| `children` | Node[] | 子节点，可为空 |

> 默认过滤 `visible=false` 的节点；`maxDepth=64`、`maxNodes=4000`。
> 输入法窗口不会被误取（已按 `TYPE_APPLICATION` 选择窗口）。

---

### 1.4 `POST /v1/find` — 查找单个节点

```json
// 请求
{"selector": {"text": "网络和互联网"}, "timeoutMs": 3000}

// 200 命中
{"ok": true, "node": {"class": "android.widget.TextView", "text": "网络和互联网",
  "desc": "", "id": "android:id/title", "pkg": "com.android.settings",
  "bounds": [320, 544, 800, 661], "clickable": false, "enabled": true}}

// 200 未命中
{"ok": false, "error": "NOT_FOUND"}
```

---

### 1.5 `POST /v1/findall` — 批量查找

```json
// 请求
{"selector": {"clickable": true}, "timeoutMs": 0, "limit": 200}

// 200
{"ok": true, "count": 8, "nodes": [ ... Node 摘要 ... ]}
```

`limit` 默认 200，达到上限立即返回；`count` 是实际匹配数（≤ limit）。

---

### 1.6 `POST /v1/wait` — 等待出现 / 消失

```json
// 请求
{"selector": {"text": "互联网"}, "state": "appear", "timeoutMs": 8000}

// 200
{"ok": true, "state": "appear", "elapsedMs": 459}
{"ok": false, "state": "timeout", "elapsedMs": 8000}
```

`state` 取值：`appear`（默认）/ `gone`。轮询间隔 150ms。

---

### 1.7 `POST /v1/waitstable` — 等界面静止

```json
{"timeoutMs": 5000, "quietMs": 300}
// 200
{"ok": true, "elapsedMs": 806}
```

判定：连续两次 dump 的根节点 JSON 完全一致，且保持 `quietMs`。
**用于消除"界面还在动画时 dump 到半截树"的假失败。**

---

### 1.8 `POST /v1/scroll` — 滚动查找

```json
{"selector": {"text": "系统"}, "down": true, "maxSwipes": 8, "timeoutMs": 1500}
// 200
{"ok": true, "node": {"...": "同 find"}}
// 未找到
{"ok": false, "error": "NOT_FOUND"}
```

硬上限 12 秒；`down=true` 表示向下滚动（内容上移）。

---

### 1.9 `POST /v1/click` — 点击

```json
{"selector": {"text": "网络和互联网"}, "timeoutMs": 3000}
{"x": 720, "y": 1200}
{"selector": {"text": "确定"}, "retries": 2, "retryIntervalMs": 300, "opId": "op-1"}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `retries` | int | 重试次数（0~5），仅对 `NOT_FOUND` / `ACTION_FAILED` / `TIMEOUT` 生效 |
| `retryIntervalMs` | int | 重试间隔，默认 300，上限 5000 |
| `opId` | string | 操作 id，可用 `/v1/cancel` 中断 |

响应带 `attempts`：

```json
{"ok": false, "error": "NOT_FOUND", "attempts": 3, "elapsedMs": 912}
```

行为：优先找 `clickable` 的祖先节点执行 `ACTION_CLICK`；失败则按节点中心坐标下发手势。
坐标模式直接下发手势。返回 `{"ok": true}` 或 `{"ok": false}`。

### 1.16 截图（整屏 / 节点级）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/screenshot` | 整屏 PNG |
| POST | `/v1/screenshot` | 支持裁剪与原始像素，见下表 |

```json
{"selector": {"text": "在设置中搜索"}, "padding": 8, "format": "png"}
{"format": "raw"}
```

| 字段 | 说明 |
|---|---|
| `selector` | 省略为整屏；传入则按该节点 `bounds` 裁剪（借鉴 assists-mp 的节点截图） |
| `padding` | 裁剪外扩像素，默认 0 |
| `format` | `png`（默认，返回二进制）或 `raw`（返回 JSON，含宽高与 RGBA base64） |

`raw` 响应：

```json
{"ok": true, "format": "raw", "width": 512, "height": 117, "base64": "..."}
```

> - 依赖 API 30+ 的 `takeScreenshot`，`FLAG_SECURE` 页面会失败
> - 系统对截图有频率限制，引擎内部做了退避重试（最多 2 次）
> - 错误码：`NODE_NOT_FOUND`（选择器没命中）/ `SCREENSHOT_FAILED`（截图本身失败）

---

### 1.17 `POST /v1/gesture` — 多指 / 多段手势

模型借鉴 AutoJs6 的 `gestures()`：每条 stroke 有独立的开始延迟与时长，**相同 `startDelayMs` 会同时按下**。

```json
{
  "strokes": [
    {"points": [[720, 1900], [720, 800]], "startDelayMs": 0, "durationMs": 400},
    {"points": [[520, 1280], [620, 1280]], "startDelayMs": 0, "durationMs": 400}
  ]
}
```

```json
{"ok": true, "strokes": 2, "elapsedMs": 402}
```

限制：`startDelayMs` 0~10000，`durationMs` 1~10000；最多 10 条 stroke（系统限制）。

---

### 1.18 `POST /v1/drag` — 拖拽

```json
{"from": [720, 2000], "to": [720, 900], "holdMs": 500, "durationMs": 400}
```

实现：先用 continuation 表达"按住再移动"；部分 ROM 不支持 continuation，自动降级为单段拖拽（日志会提示）。

---

### 1.19 `POST /v1/pinch` — 双指缩放

```json
{"center": [720, 1280], "fromRadius": 200, "toRadius": 600, "durationMs": 400}
```

`toRadius > fromRadius` 为放大，反之为缩小。

---

### 1.20 `POST /v1/shell` — 设备侧 shell（需 Shizuku / root）

```json
// 请求
{"cmd": "pm list packages -3", "timeoutMs": 30000}

// 200
{"ok": true, "exitCode": 0, "stdout": "package:com.foo\n", "stderr": "",
 "kind": "shizuku", "elapsedMs": 152}

// 无通道
{"ok": false, "exitCode": -1, "stderr": "SHELL_UNAVAILABLE", "kind": "none", "elapsedMs": 0}
```

---

### 1.21 `POST /v1/cancel` — 取消操作

```json
// 取消指定操作
{"opId": "op-1"}
{"all": true}
```

```json
{"ok": true, "cancelled": 1}
```

长任务（`wait` / `waitstable` / `scroll` / 带重试的动作）才需要 `opId`；
未注册或已结束的 id 返回 `{"ok": false, "cancelled": 0}`。

### 1.22 `GET /v1/ops` — 运行中的操作

```json
{"ok": true, "running": ["op-1"]}
```

用于排查"卡住的是哪个操作"。

## 2. 编排器接口（:7920）

### 2.1 `GET /v1/capabilities`

```json
{
  "ok": true,
  "channels": {
    "ui":    {"available": true, "state": "ready", "transport": "reverse-hub"},
    "shell": {"available": true, "kind": "adb-shell", "via": "adb"},
    "logcat":{"available": true}
  },
  "device": {"serial": "emulator-5554", "model": "<设备型号>", "sdk": "35"}
}
```

`shell.kind`：`adb-shell`（uid=2000）/ `adb-root`（uid=0）/ `none`。
`ui.state`：`ready` / `accessibility_not_ready` / `unreachable`。

---

### 2.2 `POST /v1/shell`

```json
{"cmd": "dumpsys window displays | head -3", "timeoutMs": 20000}
// 200
{"ok": true, "exitCode": 0, "stdout": "...", "stderr": "", "elapsedMs": 210, "cmd": "...", "kind": "adb"}
```

无 ADB 时自动回落到设备侧 `/v1/shell`（Shizuku）。

---

### 2.3 `GET /v1/logcat`

```
GET /v1/logcat?lines=200&filter=AndroidRuntime
```
```json
{"ok": true, "lines": ["...", "..."], "stderr": ""}
```

## 3. 反连协议（TCP，:7913）

一行一个 JSON（`\n` 分隔），UTF-8。

```
设备 → hub : {"type":"hello","token":"<令牌>","device":{"model":"...","brand":"...","sdk":35}}
hub → 设备 : {"id":"1","cmd":"click","payload":{"selector":{"text":"设置"}}}
设备 → hub : {"id":"1","ok":true}
```

- `cmd` 与第 1 节的路径去掉 `/v1/` 前缀后一致（`app/current` → `app.current`）。
- `id` 由 hub 生成，设备原样回传。
- 令牌不匹配时 hub 直接断开，不返回业务响应。
- 当前无心跳；离线靠调用失败判定（见技术债）。

## 4. 事件推送（WebSocket）

设备侧把无障碍事件经反连通道上行，hub 通过 WebSocket 广播。

### 4.1 `GET /v1/events`（升级为 WebSocket）

```
ws://127.0.0.1:7912/v1/events
X-Auth-Token: <令牌>
```

连接建立后会**先补发最近 20 条**，之后实时推送。服务端每 20s 空闲发一次 ping 帧。

```json
{
  "event": {"type": "window", "package": "com.android.settings", "class": "...", "ts": 1730000000000},
  "device": {"model": "<设备型号>"}
}
```

### 4.2 `GET /v1/events/recent?limit=50`

补齐订阅前发生的事件。

```json
{"ok": true, "events": [{"event": {...}, "device": {...}}]}
```

### 4.3 事件类型

| `event.type` | 触发 | 字段 |
|---|---|---|
| `window` | 界面切换（`TYPE_WINDOW_STATE_CHANGED`） | `package`、`class`、`ts` |
| `notification` | 通知栏消息 | `package`、`text`、`ts` |
| `toast` | Toast 弹出 | `package`、`text`、`ts` |

> 事件是**尽力而为**的：通道断开时直接丢弃，不排队、不重发。需要可靠状态请用 `/v1/hierarchy` 或 `/v1/app/current`。

## 5. 变更约定

- 新增字段：只增不改，旧客户端忽略即可。
- 破坏性变更：路径升级为 `/v2/`，`/v1/` 保留一个版本周期。
- 每次变更同步更新本文档、`openapi.yaml`、`docs/需求与计划.md`。
